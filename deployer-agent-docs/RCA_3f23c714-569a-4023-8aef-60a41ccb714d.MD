Both must be resolved before this app can deploy.

## Blocker 2 (underlying, will fail the build even after credits are added) — Next.js prerender fetch failure
Across all 4 prior runs (run_ids 3f23c714, 1de0b82d, 621ba791, 1ae9abdf) the Cloud Build
failed at step #15 `yarn build` → `next build`, during static page generation:

```
Error occurred prerendering page "/luxury-home-cinema".
[TypeError: fetch failed] { digest: '3227098399',
  [cause]: AggregateError: ... { code: 'ECONNREFUSED', ... } }
Export encountered an error on /luxury-home-cinema/page: /luxury-home-cinema, exiting the build.
⨯ Next.js build worker exited with code: 1
```

Template: `nextjs_mongo_shadcn_base_image` (Next.js 16.3.2, Turbopack). The route
`/luxury-home-cinema` performs a server-side `fetch` during static generation (SSG). At
build time there is no backend/DB listening, so the fetch is refused (`ECONNREFUSED`) and
the build aborts. Compilation and TypeScript both pass — the failure is purely the
build-time data fetch, not a compile error.

**Owner: Code (E1 applies in source).** Options, any one resolves it:
- Mark the offending route(s) as dynamic so they are not prerendered at build time:
  add `export const dynamic = 'force-dynamic'` (and/or `export const revalidate = 0`)
  to the `/luxury-home-cinema` page (and any sibling pages doing the same build-time fetch).
- Or move the data fetch to request time / client side, or guard it so a failed/unavailable
  fetch during build falls back instead of throwing.
- Since 241 pages are being generated, audit whether other dynamic routes do the same
  build-time fetch and will fail the same way once this one is fixed.

Not reproduced in an eph sandbox: reproduction would require the full Next.js production
build plus a reachable backend/DB, which the sandbox has no secrets/DB for. Diagnosis is
from the consistent, identical build output across all 4 runs.
